# MB Research Intelligence

A login-first market intelligence platform for subscribed real estate developers, by **MB Research, Magicbricks**. The root URL opens the sign-in page. From there, visitors can **log in**, **request a demo** or **explore the platform** in a public preview. Signed-in clients land on the Executive Dashboard. This build is the management showcase and runs entirely on a **synthetic demonstration dataset**.

> **Every figure in this build is demonstration data.** It is generated by a seeded algorithm and does not represent Magicbricks or MB Research market statistics. City and locality names are used for realism only.

## Routes

| Route | Access | What it is |
|---|---|---|
| `/` | Public | Sign-in page: Login · Request a Demo · Explore Platform |
| `/preview`, `/preview/[module]` | Public | Explore Platform: every dashboard module on demonstration data, with a route back to sign-in |
| `/dashboard`, `/dashboard/analyst/[module]` | Signed in | Client workspace: Executive Dashboard + Detailed Analyst Dashboard |
| `/admin`, `/admin/[section]` | Signed in (admin) | Admin console: datasets, cities, micromarkets, clients, subscriptions, permissions |

Analyst modules: `demand · supply · price · bhk · ticket-size · property-size · micromarkets · history · comparison`.

### Demo access (showcase only)

On the sign-in page, under **Demonstration access**:

- **Enter demo dashboard** opens the client analyst persona at `/dashboard`.
- **Admin demo** opens the MB administrator persona at `/admin`.
- **Fill demo account** fills in the demonstration credentials (`NEXT_PUBLIC_DEMO_EMAIL` / `NEXT_PUBLIC_DEMO_PASSWORD`).

Demo access is **frontend-only** and labelled as such in the UI. It is not production authentication.

### Route protection

`middleware.ts` runs before any `/dashboard` or `/admin` page renders. Without a session it redirects to `/?next=<path>`, and after sign-in the user returns to that page.

- **Showcase:** the session marker is a demo cookie (`mbri_session`, see `lib/auth/session-cookie.ts`) set at demo sign-in. It keeps casual visitors out by direct URL but is **not** a security boundary.
- **Production:** implement `AuthService` (`lib/auth/types.ts`) with Supabase Auth or another provider, issue a signed HttpOnly session cookie, and verify it in `middleware.ts` instead of checking that the cookie is present. Organisation, role and subscription checks belong there and in database row-level security.

### Request a Demo

The form (`components/forms/demo-request-dialog.tsx`) validates in the browser and submits through `EnquiryService` (`lib/services/enquiry-service.ts`). The showcase implementation does not send or store anything, and the UI says so. To go live, implement `EnquiryService` against an API route that writes to your CRM. `validateDemoRequest` can be reused server-side.

## Brand assets

The official logos are in `public/logos/` and are configured in `lib/config/site.ts → logos`. They are displayed unaltered, without recolouring, redrawing or distortion. The supplied PNGs carry wide white margins, so each `mark` setting frames the logo region on screen. When higher-resolution or SVG originals are available, replace the files, update `width`/`height`, and set `mark` to the full image.

## Data architecture

```
components  ──►  MarketDataService (interface, async)
                    ├── DemoMarketDataService ──► AnalyticsEngine ──► demo repository (seeded generator)
                    └── ApiMarketDataService  ──► /v1/* REST endpoints (to be built)
```

- **Components never import data.** They call `getMarketDataService()` and receive typed results.
- **One fact table, one engine.** Each record sits at the grain *micromarket × quarter × property type × BHK × unit-size variant*, with measures `demand, supply, average_price, price_change, inventory`.
- **Consistent units.** Demand and supply are units in the period. Price is ₹/sq ft, supply-weighted when aggregated. Inventory is unsold stock at period end.
- **Reconciliation.** Breakdowns, cross-tabs and micromarket series sum exactly to the headline totals across all tested filter combinations.
- **Observations are derived, not written** (`lib/analytics/observations.ts`).

### Swapping in real data

1. Implement the `/v1/*` endpoints listed in `lib/services/api-market-data-service.ts`.
2. Set `NEXT_PUBLIC_DATA_PROVIDER=api` and `NEXT_PUBLIC_API_BASE_URL`.
3. No dashboard component changes are needed. The preview should keep using demonstration data (wire it to `getDemoService()` when the live provider is enabled).

### Future backend integration (planned)

- **PostgreSQL / Supabase:** `market_facts` matching `MarketRecord`, plus `cities`, `micromarkets`, `dataset_versions`.
- **Auth and access:** organisation-level accounts, roles (`client_analyst`, `client_admin`, `mb_analyst`, `mb_admin`) and subscription entitlements (city scope, modules, exports), enforced in middleware and row-level security.
- **Data ingestion:** a server-side pipeline reusing `lib/admin/dataset-validation.ts`, with versioned publishing, rollback and historical retention.

## Workspace filters

Filters are contextual. Each view shows only the filters relevant to it (`lib/config/workspace-nav.ts`), and filters a view does not show are reset to "all" for that view. Available dimensions are city, micromarket, year, quarter, configuration (BHK), ticket size and property size.

## Quality notes

- Every chart has a table view (accessible equivalent), PNG export and CSV export.
- The chart palette is validated for colour-vision deficiency and contrast on white.
- Keyboard: skip links, focus rings, arrow-key segmented controls and menus, focus-trapped dialogs. Reduced motion is respected.
- The demo admin console persists to `localStorage` only and says so in the UI.
