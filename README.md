# MB Research Intelligence

Enterprise real estate market intelligence platform by **MB Research, Magicbricks**. This is the showcase build for senior management review. It includes the public website, a demo client workspace (Executive and Analyst dashboards) and an admin console, all running on a **synthetic demonstration dataset**.

> **Every figure in this build is demonstration data.** It is generated by a seeded algorithm and does not represent Magicbricks or MB Research market statistics. City and locality names are used for realism only.

### Demo access

Open **/login** and choose one of these options:

- **Enter demo workspace** opens the client analyst persona at `/dashboard`.
- **Admin console** opens the MB administrator persona at `/admin`.
- Or sign in with the demonstration account shown on the page (`NEXT_PUBLIC_DEMO_EMAIL` / `NEXT_PUBLIC_DEMO_PASSWORD`).

Demo access is **frontend-only** and labelled as such in the UI. It stores a flag in browser storage and protects nothing. It is not production authentication.

## Deployment (GitHub → Vercel)

1. Push this repository to GitHub.
2. In Vercel, use **Add New → Project** and import the repository. The framework preset is detected as Next.js, and no build settings need changing.
3. Add `NEXT_PUBLIC_SITE_URL` (for example `https://research.example.com`). Everything else is optional.
4. Deploy. Every route is either static or client-rendered, so no server resources are needed.

## Data architecture

```
components  ──►  MarketDataService (interface, async)
                    ├── DemoMarketDataService ──► AnalyticsEngine ──► demo repository (seeded generator)
                    └── ApiMarketDataService  ──► /v1/* REST endpoints (to be built)
```

- **Components never import data.** They call `getMarketDataService()` and receive typed results (`KpiSet`, `TrendPoint[]`, `BreakdownRow[]`, …).
- **One fact table, one engine.** Each record sits at the grain *micromarket × quarter × property type × BHK × unit-size variant*, with dimensions `city_id, micromarket_id, reporting_year, reporting_quarter, property_type, bhk_configuration, ticket_size_bracket, property_size_bracket` and measures `demand, supply, average_price, price_change, inventory`, plus `unit_size_sqft` and `ticket_size_inr` so brackets can be re-bucketed at query time.
- **Consistent units.** Demand and supply are units in the period. Price is ₹/sq ft, supply-weighted when aggregated. Inventory is unsold stock at period end. The D/S ratio is demand ÷ supply.
- **Reconciliation.** Every breakdown sums exactly to the KPI totals, and shares sum to 100%. This was verified across all 2,016 filter combinations.
- **Observations are derived, not written.** `lib/analytics/observations.ts` applies thresholds to the computed numbers, and each observation carries its evidence.

### Swapping in real data

1. Implement the `/v1/*` endpoints listed in `lib/services/api-market-data-service.ts`. They are thin wrappers that run the same `AnalyticsEngine` over database rows, or equivalent SQL.
2. Set `NEXT_PUBLIC_DATA_PROVIDER=api` and `NEXT_PUBLIC_API_BASE_URL`.
3. No dashboard component changes are needed.

### Future backend integration (planned)

- **PostgreSQL / Supabase:** a `market_facts` table matching `MarketRecord`, plus `cities`, `micromarkets` and `dataset_versions`.
- **Auth:** a `SupabaseAuthService` implementing `AuthService` (`lib/auth/types.ts`), with server-validated sessions and middleware route protection.
- **Role-based and organisation-level access:** roles `client_analyst`, `client_admin`, `mb_analyst`, `mb_admin`, enforced with row-level security keyed to organisation and subscription entitlements (city scope, modules, exports). The admin **Access Permissions** matrix models this.
- **Monthly or quarterly uploads:** a server-side ingestion pipeline reusing the rules in `lib/admin/dataset-validation.ts`, with Excel parsing, staging tables, validation, publishing as a new version, rollback, and historical retention.
- **Subscriptions:** plans and assignments as modelled in the admin console, with billing integration.

## Quality notes

- Every chart has a table view (accessible equivalent), PNG export and CSV export. The header Export menu lists every dataset on the current view.
- The chart palette was validated for colour-vision deficiency and contrast against the dark chart surface. Colour follows the entity: demand is blue, supply is orange and price is aqua. Compared micromarkets keep their colour when the selection changes.
- Keyboard: skip links, focus rings, arrow-key segmented controls and menus, and focus-trapped dialogs. The app respects `prefers-reduced-motion`.
- The demo admin console persists to `localStorage` only and says so in the UI.
